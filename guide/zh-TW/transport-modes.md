## 傳輸模式概述

### 什麼是傳輸模式？

傳輸模式決定了資料如何在客戶端和 Edge 伺服器之間傳輸。

YAT 支援三種傳輸模式：

1. **Relay（中繼）** - 通過 Edge 伺服器轉發
2. **P2P（點對點）** - 裝置間直連
3. **WireGuard** - VPN 隧道

### 底層協議

所有模式都使用 **mTLS over TCP** 作為底層傳輸：

- ✅ 雙向 TLS 認證
- ✅ 加密傳輸
- ✅ 防中間人攻擊

---

## 中繼模式（Relay）

### 工作原理

```
客戶端 A ──mTLS──► Edge 伺服器 ──mTLS──► 客戶端 B
```

所有流量都經過 Edge 伺服器中轉。

### 特點

| 特性 | 說明 |
|------|------|
| **延遲** | 中（增加 Edge 往返時間） |
| **頻寬** | 受 Edge 頻寬限制 |
| **穩定性** | 高（Edge 通常網路穩定） |
| **NAT 穿透** | 無需穿透 |
| **防火牆** | 只需 Edge 開放埠 |

### 適用場景

- ✅ 跨地域訪問
- ✅ 網路環境複雜
- ✅ 需要高穩定性
- ✅ Web 服務（HTTP/HTTPS）

## P2P 直連模式

### 工作原理

```
客戶端 A ──mTLS──► 客戶端 B（直連）
         ▲
         │
      Edge（僅協調）
```

Edge 僅負責初始連線協調，後續流量直連。

### NAT 穿透

P2P 模式使用 **ICE/STUN/TURN** 技術穿透 NAT：

1. **STUN** - 獲取公網 IP
2. **ICE** - 候選地址收集
3. **TURN** - 穿透失敗時回退到中繼

### 特點

| 特性 | 說明 |
|------|------|
| **延遲** | 低（直連，無中轉） |
| **頻寬** | 高（受兩端頻寬限制） |
| **穩定性** | 中（依賴 NAT 型別） |
| **NAT 穿透** | 需要穿透 |
| **防火牆** | 可能需要配置 |

### 適用場景

- ✅ 區域網或同地域
- ✅ 需要低延遲（遠端桌面）
- ✅ 大檔案傳輸
- ✅ 音影片流

### NAT 型別相容性

| NAT 型別 | P2P 成功率 |
|---------|-----------|
| 全錐型 | ✅ 高 |
| 受限錐型 | ✅ 中 |
| 埠受限 | ⚠️ 低 |
| 對稱型 | ❌ 很低 |

## WireGuard 模式

### 工作原理

```
客戶端 A ──WireGuard──► 虛擬網絡卡 ──轉發──► 本地服務
                                    ▲
                                    │
                                 Edge（協調）
```

使用 WireGuard VPN 建立虛擬區域網。

### 特點

| 特性 | 說明 |
|------|------|
| **延遲** | 低 |
| **頻寬** | 很高 |
| **穩定性** | 高 |
| **安全性** | 極高（核心級加密） |
| **配置複雜度** | 中 |

### 適用場景

- ✅ 大檔案傳輸
- ✅ 資料庫同步
- ✅ 多服務訪問
- ✅ 需要虛擬區域網

### 配置要求

**Edge 伺服器**：
```bash
# 安裝 WireGuard
sudo apt install wireguard

# 載入核心模組
sudo modprobe wireguard
```

**客戶端**：
- macOS: 安裝 WireGuard.app
- Windows: 安裝 WireGuard
- Linux: 安裝 wireguard-tools

## 模式對比

### 效能對比

| 模式 | 延遲 | 頻寬 | CPU 佔用 |
|------|------|------|---------|
| **Relay** | 50-200ms | 10-100Mbps | 中 |
| **P2P** | 5-50ms | 100-1000Mbps | 低 |
| **WireGuard** | 5-30ms | 500-2000Mbps | 極低 |

### 相容性對比

| 模式 | NAT 穿透 | 防火牆 | 行動網路 |
|------|---------|--------|---------|
| **Relay** | ✅ 不需要 | ✅ 友好 | ✅ 支援 |
| **P2P** | ⚠️ 需要 | ⚠️ 可能受阻 | ⚠️ 不穩定 |
| **WireGuard** | ⚠️ 需要 | ⚠️ UDP 443 | ✅ 支援 |

### 協議支援

| 模式 | HTTP | TCP | UDP | WireGuard |
|------|------|-----|-----|-----------|
| **Relay** | ✅ | ✅ | ✅ | ✅ |
| **P2P** | ✅ | ✅ | ✅ | ❌ |
| **WireGuard** | ✅ | ✅ | ✅ | ✅ |

## 如何選擇

### 決策樹

```
是否需要低延遲？
├─ 是 → 同地域？
│       ├─ 是 → P2P 模式
│       └─ 否 → WireGuard 模式
└─ 否 → 需要高穩定性？
        ├─ 是 → Relay 模式
        └─ 否 → P2P 模式
```

### 推薦配置

| 場景 | 推薦模式 | 原因 |
|------|---------|------|
| **Web 服務** | Relay | 穩定、相容性好 |
| **遠端桌面** | P2P | 低延遲 |
| **資料庫** | WireGuard | 高頻寬、安全 |
| **檔案傳輸** | WireGuard | 速度快 |
| **API 除錯** | Relay | 簡單易用 |
| **遊戲伺服器** | P2P | 低延遲 |

### 自動回退

YAT 支援自動回退機制：

```
P2P 嘗試失敗
  ↓
回退到 Relay
  ↓
保持連線
```

## 常見問題

### Q: 如何切換傳輸模式？

目前**不支援**執行時切換，需要：
1. 停止隧道
2. 刪除隧道
3. 重新建立並選擇新模式

### Q: P2P 模式連線失敗怎麼辦？

**原因**: NAT 穿透失敗

**解決**:
1. 檢查 NAT 型別
2. 嘗試在相同網路下
3. 使用 Relay 模式作為備選

### Q: WireGuard 模式需要額外配置嗎？

**需要**:
1. 安裝 WireGuard
2. 開放 UDP 埠（預設 51820）
3. 配置防火牆

### Q: 哪種模式最安全？

**WireGuard > P2P > Relay**

- WireGuard: 核心級加密，經過嚴格審計
- P2P: mTLS 加密，直連無中轉
- Relay: mTLS 加密，但經過 Edge

### Q: 行動網路下使用哪種模式？

推薦 **Relay** 或 **WireGuard**：
- 行動網路 NAT 型別複雜，P2P 成功率低
- WireGuard 對行動網路最佳化好
