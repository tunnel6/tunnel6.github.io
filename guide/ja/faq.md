# FAQ

## 初期設定

### サインインできない
ネットワーク接続、システム時刻、ブラウザーから GitHub または Google を開けるか確認してください。認証後にクライアントへ戻らない場合は、表示されたリンクを手動で開きます。

### 利用できる Edge がない
公式 Edge または共有 Edge を購読してください。自前 Edge を使う場合は、プロセスとコンソール上のオンライン状態を確認します。

### トンネルが起動しない
1. ローカルサービスが応答するか確認
2. ローカルアドレスとポートを確認
3. リモートポートが重複していないか確認
4. Edge の状態を確認

## 接続

### 接続が不安定
一時的に `Relay Mode` に変更してください。改善する場合は、ネットワークが P2P 経路を維持できていません。

### HTTP が 502 を返す
Edge には到達していますが、ローカルサービスが応答していません。

```bash
curl -I http://127.0.0.1:3000
```

### TCP 接続が拒否される
リモートポート、ファイアウォール、Edge のリスナーを確認してください。

### UDP でパケット損失が大きい
遅延と損失率を計測してください。回線品質が悪い場合は TCP または Relay Mode を検討します。

## ドメインと証明書

### CNAME が検証されない
[DNS トラブルシューティング](./dns-troubleshooting.md) を参照してください。同じ名前の A レコードがないことと、DNS 伝播の完了も確認します。

### 証明書が期限切れになる
YAT は 30 日前に自動更新します。手動で更新するには：

```bash
./edge certs renew --config config.yaml
```

### Edge を変えたらドメインが動かない
CNAME は特定の Edge を指します。新しい値へ DNS レコードを更新してください。

## WireGuard

### メンバー同士が見えない
1. Edge で WireGuard が有効か確認
2. 両メンバーが同じネットワークに所属しているか確認
3. IP 転送とファイアウォールを確認

### ping は通るがポートが応答しない
WireGuard の経路は機能しています。対象サービスの待ち受け状態とシステムのファイアウォールを確認してください。

### Docker が転送をブロックする
`DOCKER-USER` と nftables / iptables legacy の関係を確認してください。詳細は [Edge WireGuard 設定](./edge/wireguard.md#docker-host-iptables-interference) にあります。

## パフォーマンス

### Edge の CPU 使用率が高い
接続数を減らし、ログレベルを `WARN` または `ERROR` に下げ、実際のトラフィックに見合うハードウェアへ増強します。

### メモリ使用率が高い
キャッシュ、未解放接続、大容量転送を確認してください。大きなファイルにはストリーミングを使います。

### レイテンシが高い
P2P Direct を試し、近い Edge を選び、ネットワーク品質を確認してください。

## アカウントと権限

### デバイスを削除するには？
デバイス管理画面から不要なインストールを削除します。

### トンネルを共有するには？
共有設定から対象を追加し、必要最小限のロールを割り当てます。
