# 📜 証明書管理ガイド

> 証明書は通信の安全性を支える基盤です。有効期限を定期的に確認し、期限切れの前に更新してサービス断を避けてください。

## 🔐 YAT の証明書構成

YAT は相互 TLS（mTLS）ですべての通信を保護します。
- **Root CA 証明書**：他のすべての証明書を発行するルート証明書
- **Edge TLS 証明書**：HTTPS アクセスに使う Edge ノードの TLS 証明書
- **gRPC 証明書**：gRPC サービス間の通信を保護する証明書
- **クライアント証明書**：クライアント認証に使う証明書

## 📅 証明書のライフサイクル

### 自動管理
YAT は証明書の発行と更新を自動化できます。
- **Let's Encrypt**：無料の SSL/TLS 証明書を自動取得
- **自動更新**：有効期限の 30 日前に更新を開始
- **状態監視**：証明書の有効期限を常時確認

### 手動管理
手動で操作する必要がある場合は次のコマンドを使います。
```bash
# 証明書情報を確認
./edge certs info --config config.yaml

# 証明書を手動更新
./edge certs renew --config config.yaml

# 証明書を再生成
./edge certs generate --config config.yaml
```

## 🚨 よくある問題

### 証明書の期限切れ
- **症状**：ブラウザーに「この接続ではプライバシーが保護されません」または `NET::ERR_CERT_DATE_INVALID` と表示される
- **対処**：
  - 通常は期限 30 日前の自動更新を待つ
  - `./edge certs renew` を手動実行する
  - システムの時刻が正しいか確認する

### 証明書とドメインの不一致
- **症状**：`NET::ERR_CERT_COMMON_NAME_INVALID` が表示される
- **対処**：
  - 証明書のドメインとアクセスするドメインが完全に一致しているか確認する
  - CNAME レコードが正しい Edge ノードを指しているか確認する
  - 正しいドメインを指定して証明書を再生成する

## 🛠️ 運用のポイント

- **ドメイン設定**：利用するすべてのドメイン（通常ドメインと `www` サブドメイン）を含める
- **鍵の保護**：秘密鍵ファイルの権限を `600` に設定する
- **バックアップ**：証明書と秘密鍵を定期的に保存する
- **アラート**：有効期限 7 日前に通知を出す
