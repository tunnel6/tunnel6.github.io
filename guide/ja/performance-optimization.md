# ⚡ パフォーマンス最適化ガイド

> チャネル数と帯域制限は実際の利用状況に合わせて調整してください。CPU、メモリ、ネットワークを継続的に監視すると、ボトルネックを早く発見できます。

## 📊 監視すべき指標

### 主要な指標
- **CPU 使用率**：Edge ノードの CPU 占有率
- **メモリ使用率**：Edge ノードのメモリ占有率
- **ネットワーク帯域**：リアルタイムの上り／下り通信量
- **接続数**：現在アクティブな接続数
- **レイテンシ**：エンドツーエンドの RTT

### 監視ツール
- YAT コンソールのリアルタイム監視パネル
- プロセス監視：`top` / `htop`
- ネットワーク流量監視：`iftop`
- ディスク I/O 監視：`iostat`

## 🛠️ 最適化の方針

### 1. Edge ノード

#### 設定
```yaml
# config.yaml
performance:
  max_connections: 1000          # 最大接続数
  bandwidth_limit: 100mbps       # 帯域制限
  keep_alive: 30s                # keep-alive 間隔
  worker_threads: 4              # ワーカースレッド数
```

#### ハードウェア
- **CPU**：最低 2 コア。高並行では 4 コア以上を推奨
- **メモリ**：最低 2 GB。同時接続 100 件ごとに 512 MB を追加
- **ディスク**：ログ書き込みの遅延を避けるため SSD を使用
- **ネットワーク**：1 Gbps インターフェースと十分な上り帯域

### 2. トンネル

#### トランスポートモードの選択
| シナリオ | 推奨モード | 理由 |
|----------|------------|------|
| LAN 内 | P2P Direct | 遅延が最も低く性能が高い |
| モバイルネットワーク | Relay Mode | 安定性と互換性に優れる |
| 複雑な NAT | Relay Mode | P2P の成功率が下がる |
| 高いセキュリティ要件 | Relay Mode | 通信が Edge ノード経由になる |

#### チャネル設定
- **数**：必要な分だけ作成し、未使用チャネルによる無駄を避ける
- **帯域割り当て**：重要なサービスに高い優先度を設定する
- **タイムアウト**：現実的な値を設定して未使用接続を解放する

## 🚨 問題の診断

### CPU 使用率が高い
- **考えられる原因**：
  - 接続数が多すぎる
  - 暗号化処理が重い
  - ログレベルが詳細すぎる
- **対処**：
  - 最大接続数を制限する
  - ハードウェアを増強する
  - ログレベルを `WARN` または `ERROR` に変更する

### メモリ使用率が高い
- **考えられる原因**：
  - キャッシュが大きすぎる
  - 接続が解放されていない
  - 大容量ファイル転送
- **対処**：
  - キャッシュサイズを調整する
  - 接続管理を確認する
  - 大きなファイルにはストリーミング転送を使う
