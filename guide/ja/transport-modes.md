# トランスポートモードとプロトコル

> アプリケーション種別、ネットワーク環境、遅延・安定性・セキュリティの優先度に合わせてモードを選択します。

## 概要

| モード | 動作 | 利点 | 制約 |
|--------|------|------|------|
| HTTP | ドメインごとに HTTP/HTTPS を転送 | ドメインと証明書に統合 | HTTP 通信のみ |
| TCP | 公開ポートからローカルポートへ転送 | DB、SSH、RDP などに対応 | Edge にポートが必要 |
| UDP | UDP データグラムを転送 | ゲーム、DNS、ストリーミングに適する | パケット損失の影響を受けやすい |
| P2P Direct | 両端の直接接続を試みる | 低遅延で Edge 負荷が小さい | NAT とファイアウォール次第 |
| Relay Mode | すべての通信が Edge 経由 | 安定し、複雑な NAT でも機能 | Edge の帯域を消費 |
| WireGuard | 暗号化された仮想 LAN を構築 | メンバー間で双方向通信 | カーネルまたはユーザー空間の対応が必要 |

## 選び方

| 目的 | 推奨 |
|------|------|
| Web サイトや API | HTTP |
| データベース、SSH、RDP | TCP |
| ゲーム、VoIP、自前 DNS | UDP |
| 単純なネットワーク間の直接通信 | P2P Direct |
| モバイル回線や厳しい NAT | Relay Mode |
| 複数内部サービスをまとめて利用 | WireGuard |

## HTTP

Web サービスには HTTP が最も扱いやすいモードです。システム割り当てドメインまたは独自ドメインを使えます。Edge は TLS を終端し、証明書を適用して、リクエストをローカルサービスへ転送します。

## TCP

TCP は Edge の公開ポートとローカルポートの間でストリーム接続を維持します。利用前に次を確認してください。

```bash
# ローカルサービスの待ち受け確認
lsof -i :3306

# リモートポートの確認
nc -zv your-edge-domain.com 3306
```

バイナリプロトコルや持続的接続に適しています。

## UDP

UDP は再接続を管理しないデータグラム転送です。ゲーム、DNS、ストリーミングのような損失に耐性のある用途に向いています。

## P2P Direct

P2P は接続情報を交換したあと、直接経路を確立しようとします。遅延が低く、Edge の帯域消費を抑えられます。

少なくとも一方が寛容な NAT または UPnP を利用できる場合に成功しやすいです。失敗する場合は Relay Mode に切り替えてください。

## Relay Mode

Relay Mode では Edge が入口と出口になります。モバイル回線、対称 NAT、企業ファイアウォールでも安定し、通信経路を監査しやすくなります。代わりに Edge の帯域が上限になります。

## WireGuard

WireGuard は暗号化インターフェースを作成し、デバイス間の双方向通信を可能にします。複数サービスを同じ LAN 上のように扱いたい場合に便利です。

確認ポイント：

- Edge で WireGuard が有効であること
- カーネルが IP 転送をサポートしていること
- YAT インターフェースがファイアウォールで許可されていること
- Docker 環境では `FORWARD` と `DOCKER-USER` の規則を確認

詳細は [WireGuard ネットワーク](./wireguard-networking.md) と [Edge WireGuard 設定](./edge/wireguard.md) を参照してください。

## 診断

| 症状 | 最初の確認 |
|------|------------|
| P2P が接続しない | 一時的に Relay Mode に変更 |
| HTTP が 502 を返す | ローカルサービスの応答を確認 |
| TCP 接続が拒否される | リモートポートと Edge ファイアウォールを確認 |
| UDP で損失が大きい | パケットロスと遅延を計測 |
| WireGuard が転送しない | IP 転送とファイアウォール規則を確認 |
