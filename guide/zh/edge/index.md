## 什么是 Edge

您的 NAS、数据库、本地开发服务都躲在内网里，公网访问不到。Edge 补的就是这一环：它部署在一台有公网地址的机器上，与您本地的 YAT 客户端之间保持一条经过 mTLS 双向认证的长连接。外部访问先到达 Edge，再顺着这条连接交给内网服务 —— 您不用给内网机器开端口，也不用去路由器上做端口转发。

```
没有 Edge：  访问者 ✗ —— 路由器没有做端口映射，请求进不来
有 Edge：    访问者 → Edge（公网入口） → 已认证的连接 → 内网服务
```

## Edge 负责什么

| 职责 | 说明 |
|------|------|
| **对外入口** | 监听 HTTP/HTTPS、TCP、UDP、WireGuard 等协议端口，接收外部访问 |
| **流量转发** | 按域名或端口把请求路由到对应的隧道，回程流量走同一条连接返回 |
| **身份与加密** | 与 Captain 控制面、客户端之间全程双向认证，信任基于身份而不是网络位置 |
| **域名分配** | 隧道自动获得系统分配的域名（如 `abc123.edge.myroxy.dev`），也可以绑定您自己的域名 |
| **状态上报** | 上报在线状态、隧道列表和流量统计，控制台据此做健康检查 |

## Edge 从哪来

| 来源 | 说明 | 适合 |
|------|------|------|
| **官方节点** | YAT 提供的多地域节点，注册账号后即可就近接入 | 大多数个人和团队场景 |
| **自建 Edge** | 部署在您自己的 VPS 上，独占带宽、端口和证书 | 生产环境、要求出口可控 |
| **共享 Edge** | 订阅您自己其他设备或他人共享出来的 Edge | 测试、临时使用 |

自建和共享都在客户端的 **Edges** 页面里管理，具体步骤见 [部署 Edge 服务器](./deploy.md) 与 [Edge 市场与共享](./market.md)。
